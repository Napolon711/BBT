# BBT 单哨兵功能演示

这是一段有明确刺激的功能演示，不是随机策略对抗赛。红方7号使用生产BBT和ROS＋PTY通信链，使用正式点表和原始出生点；其他机器人只接收停车/制动，没有策略进程。其他车仍是物理实体，受到重力、接触和弹丸冲量时可以被动移动，不通过改写位姿来冻结。导航、折叠、真实射击、购买扣款、6秒延迟到账、回家补给和复活均由原Arena库执行。演示驱动单独链接现有库，不修改Arena源码或其正式二进制。六洞连续途经点的独立物理验收另外覆盖红蓝12项。

| 演示时间 | 输入刺激与观察点 |
|---|---|
| 00:00–01:00 | 初始测试余额5000；前哨保持默认控制状态，BBT自行跨区、折叠过洞并执行前哨任务 |
| 01:00 | 按用户要求，把双方前哨的阵地与建筑所有者设为红方，观察BBT退出前哨争夺、恢复巡逻 |
| 01:25 | 哨兵HP设为35%，记录真实受伤时刻；脱战后观察自动买血、余额扣款及实际到账 |
| 02:15 | 弹量设为20，观察自动买100发、低弹回家锁存、补给与恢复巡逻 |
| 03:10 | HP设为20%，观察低血回家和第二次远程回血 |
| 03:55 | 明确注入阵亡，观察生产代码请求付费复活与引擎原地复活、弱化过程 |
| 04:20 | 通过现有操作手接口指向点34，抵达后恢复规则决策 |
| 05:00 | 演示结束，逐物理tick重放同样动作及刺激，比较完整采样帧与最终digest |

所有刺激存入 `scenario.json`，运行中事件为 `demo_stimulus`。不传送车辆，不代填导航成功或折叠完成，不直接增加买血/买弹结果。5000余额、受伤、低弹和占领属于为功能可见性设置的测试条件，应与BBT自己执行的功能区分。

```bash
cd /home/chengdong/BBT
source /opt/ros/jazzy/setup.bash
source install/setup.bash
python3 tools/run_bbt_demo.py --domain 214 --seconds 300 \
  --output runs/bbt_my_feature_demo

/home/chengdong/rl_workspace/.venv/bin/python tools/view_arena_replays.py \
  runs/bbt_my_feature_demo --port 8880
```

输出目录须不存在。该工具使用Arena现有编译库，保留源文件快照、哈希、逐步动作、回放、接口记录、场景刺激、功能验收及确定性重放报告。`timeline.json` 可用于逐时刻检查目标、过洞阶段、HP、弹量和控制权；成功验收要求真实买血/买弹到账、付费复活、回家、多个巡逻点、实际射击，以及其他机器人没有运动/射击指令。被动位移单独记录，不冒充其他策略活动。

洞中心的正确语义和实车Nav2接线见 [nav2_waypoints.md](nav2_waypoints.md)。

已完成的功能回放为 `runs/bbt_feature_demo_nav2_20261101`，所有功能验收和6000步确定性回放通过。之后另做的泊车初始化与受限巡逻集合试验分别留在 `runs/bbt_feature_demo_nav2_final_20261101`、`runs/bbt_feature_showcase_20261101`，它们暴露普通仿真导航接近墙角时的受阻，不作为完整功能展示记录。它们没有改变连续途经点12项物理验收的结果，也未据此再次修改生产决策。
