# 完整赛 v2：哨兵展开受阻诊断

范围说明：本报告解释该局的展开受阻。后续用户明确要求洞中心为不停留途经点后，另确认了旧代码逐目标下发中心的实现错误，已改用一次Nav2多点任务；见 [连续途经点修正](nav2_waypoints.md)。本报告对展开受阻的判断不能解读为旧导航输出没有其他问题。

审查对象是 `runs/bbt_full_match_20261101_v2`，种子2027，仅红方7号由BBT控制。比赛在146秒红方基地被摧毁时正常结束。本次诊断未修改BBT决策、仿真引擎或正式回放。

当前证据没有证明BBT决策或通信接口实现错误。可确认的触发链是：红方3号轮足步兵与折叠哨兵发生持续骑压接触，阻碍机构展开；引擎一直反馈已折叠，BBT因而保留过洞恢复事务、停车重试并禁火。单车六洞验收通过与本场多车受阻可以同时成立。

| 时间 | 实测行为 |
|---|---|
| 8.0秒 | 到达入口并请求折叠 |
| 8.9秒 | 收到真实已折叠反馈 |
| 13.1秒 | 洞中心到达，随后导航出口；多车碰撞使路线偏移并触发一次超时重试 |
| 59.8秒 | 出口导航成功，场地坐标为 `(9.3148745,1.0198565)`，距配置出口 `(9.32,1.0)` 为2.051厘米；BBT请求展开 |
| 59.9秒起 | 实际引擎输入持续 `crouch=false`，折叠进度仍为1.0 |
| 62.9秒起 | 展开等待3秒超时，停车取消，冷却5秒后重新请求展开 |
| 146秒 | 正常比赛终局，哨兵仍处于展开恢复事务 |

接口核对涵盖1459个相同模拟时刻：位姿、血量、折叠反馈与物理记录一致。入口、中心、出口的真实导航到达误差分别为1.426、0.885、2.051厘米，符合2.5厘米的精确到达门限。最后1722个物理动作均要求展开；反馈没有伪造机构完成。两次原地复活后也没有错误坐标或错误机构状态。

在60.05秒，按原模型、实测四元数和腿长重建碰撞形状，并用引擎同版Parry库复核，得到：

| 子形状 | 当前有符号间距 | 下一展开步有符号间距 |
|---|---:|---:|
| 哨兵底盘与红3躯干 | -12.379毫米 | 不变 |
| 哨兵底盘与红3车轮 | -11.710毫米 | 不变 |
| 哨兵折叠炮塔与红3躯干 | -10.214毫米 | -12.361毫米 |

负值表示子形状相交；这些数值不应解释为两台整车的严格最小脱离距离。它们说明该帧展开会加重队友实体冲突，不能将拒绝展开一概认定为误判。红3采用高躯干和分离腿端碰撞体；两车平面原点虽相距约8.8厘米，其主要壳体高度不同，不能只凭二维距离认定整车穿模。软接触求解允许受载后的浅层接触；静态洞顶和矩形场地障碍未命中这次形状检查。

后续对60.05至146秒的全部431个已请求展开、仍保持折叠的采样帧做形状核对，每帧的候选炮塔仍与红3相交，未发现“炮塔有净空、仅不变底盘或轮胎接触”的帧。该核对使用物理tick结束的采样姿态，不是120Hz碰撞查询前的内部微步快照；60.05秒另外用引擎同版Parry库独立验证了相交关系。

仿真仍有需要区分的局限：`simulation/src/physics.rs` 的机构展开分支查询整个候选复合形状，并要求零相交，未单独检查变化的炮塔扫掠体积。因此原本不变的底盘或轮胎接触也可能拒绝展开。但60.05秒同时存在炮塔新增运动方向受阻，源码上的保守判定不能单独证明本局起因是仿真误判。

独立离线对照保留原比赛全部输入，只从13秒起将红3驱动改为停车和制动：在相同的展开指令链下，60.05秒开始展开，60.9秒完全展开。原样对照到95.05秒仍折叠。另两组较晚停车或驶离的试验没有成功，也一并保留。试验没有传送车辆、改血量或改规则；但录制动作在分歧后是开环执行，不能据此预测闭环重赛结果，或将红3接触认定为全程唯一因素。

BBT的行为符合现有安全契约：`TunnelRunner::step()` 在整个过洞事务内禁火；只有真实反馈为Unfolded才结束事务；超时后保留出口进度并重试。缺少多车骑压脱困能力属于后续功能取舍，不能用这场失败直接证明已有状态机实现错误。本轮保留决策代码。
