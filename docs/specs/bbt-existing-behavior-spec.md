# BBT 哨兵保底决策功能规格

状态：关键行为已由用户逐项确认，本轮实现、自动化与仿真验收已完成；原生黑板重构后10项CTest及红蓝六洞双向24场通过，原坐标到达后20秒保护与解除时序通过。实机联调待验，验证记录见 `docs/specs/bbt-implementation-validation.md`。

原始规格基线：2026-11-02本地工作区，基础提交 `ae7bafd6d6482d13280b2a672d09688ce58ec3ea`，包含尚未提交的实现和工具；仅凭该提交不能复现该工作区。本文保留既有能力与用户确认的目标，原“待改”项在本轮实施；最终以对应代码提交和实际验证报告确定实现情况，历史仿真不作为改后工作区的通过证据。

## Problem Statement — 问题

操作员需要一套可独立运行的哨兵保底决策。已有导航、补给回家、前哨争夺、巡逻、折叠过洞和自主购买能力，但功能契约分散，部分旧注释落后于实现。原坐标指点吸附预设点，无法准确表达任意原坐标目标；到达即恢复自主也可能违背操作手意图，需要明确目标归属、到点作战、解除条件与重试规则。

BBT 的任务与规则独立定义。UC 仅作为通信兼容对象，约束消息类型、字段、单位、话题与线格式，不决定 BBT 的任务或目标表达。

## Solution — 方案

保留 ROS 2 Jazzy 工作区的裁判消息、串口桥、规则决策及验证工具。全部业务决策与流程执行由现有行为树体系表达，不允许另建阶段状态机，也不能把状态机包装成一个树动作冒充树实现。

操作手的任意坐标指点由 BBT 接收，借助区域几何判区，必要时按洞连接图穿越，再由导航确认到达原始坐标。到达后至少保持20秒；之后允许低血低弹回家，或在连续脱战10秒后恢复自主。自主购买全程独立运行。

人工购买直接作用于裁判系统，不经过 BBT 的购买决策。BBT 仍会自主买弹、回血与请求复活。共享裁判回读用于观察实际资源和兑换计数，不能把人工操作再执行一遍。

BBT不识别场上的敌我机器人。己方阵营由操作员开局指定，决策只据此解释裁判的红蓝前哨数据与部署战术几何；机器人检测、敌我目标识别、跟踪、瞄准和实际射击由外部自瞄系统负责。BBT现有攻击输出只表达允许开火、自由选敌或优先前哨的意图，不代表发现或识别了目标。

## User Stories — 用户故事

1. 作为操作员，我希望独立运行纯规则哨兵决策，使机器人持续执行保底任务。
2. 作为操作员，我希望开局明确选择红蓝并保持不变，使身份数据异常不会突然改变己方。
3. 作为集成人员，我希望直接使用 UC 兼容通信，使发送方不必为 BBT 裁剪数据或重排字段。
4. 作为操作员，我希望没有雷达、自瞄跟踪或指点发布者时仍能执行基本决策。
5. 作为维护者，我希望业务流程直接在树中表达，使规则优先级与执行条件可检查。
6. 作为现场工程师，我希望配置战术点、区域几何和洞连接，使同一决策适配正式场地或简单地图。
7. 作为现场工程师，我希望启动时检查非法数值和相互矛盾的配置，使错误不会静默进入运行。
8. 作为现场工程师，我希望标定场地到地图的真实变换，使定位与导航目标处于同一坐标系。
9. 作为操作员，我希望蓝方部署旋转战术几何但保持敌我含义，使同一任务适用于双方。
10. 作为操作员，我希望点击不在预设点表中的坐标，使哨兵前往我实际指定的位置。
11. 作为操作员，我希望跨区域点击也能经过必要的洞到达，使人工目标不被改成附近预设点。
12. 作为操作员，我希望洞内等无效终点被静默拒绝，使错误点击不会替换现有有效任务。
13. 作为操作员，我希望只有最终原坐标的导航成功才算到达，使洞口回执或接近目标不提前完成任务。

16. 作为操作员，我希望保护期后资源不足可以回家，使人工任务仍能让位于补给需求。

19. 作为操作员，我希望重复相同坐标不重发导航或重置计时，使重复消息不造成抖动或无限延长任务。
20. 作为操作员，我希望新坐标能替换旧目标，使人工意图及时更新。
21. 作为操作员，我希望导航失败后自动按间隔重试，使恢复不依赖再次点击同点。

## Implementation Decisions — 行为与接口契约

### 1. 实现约束与职责

- 目标选择、指点保持、计时条件、导航重试、过洞顺序和故障恢复均由行为树的条件、动作与控制节点编排。本轮移除原过洞阶段枚举及switch调度，改为树表达。
- 黑板可以保存当前指令、目标坐标、导航请求身份、到达时刻、脱战起点、重试截止时间及真实物理进度证据；不建立独立业务阶段枚举，也不用一串阶段完成标志重造隐藏状态机。
- 生产XML保持 `BehaviorTree ID="Main"`，各节点实例具有唯一语义名称。节点通过显式Input/Output/InOut端口访问原生黑板的config、io、sense、plan、execution、target领域键；每个节点只声明所用依赖。配置只读，运行状态不再保存在回调捕获的Context中。类型化初始化、重映射及中断后的状态保留见 `docs/behavior-tree-blackboard.md`。
- 每tick重新判断不等于每tick重新发命令。目标与请求去重、异步回执归属和动作幂等必须保持。子树被中止不代表洞已穿完，不能仅因树重评就清除洞内恢复证据。
- BBT 使用定位结果，不自行实现定位、实车路径规划、局部控制或自瞄。已有 UC 桥可提供输入时只运行 BBT 决策；同一物理串口只运行一个桥，同一导航控制链只运行一个决策执行器。
- 规格中的“己方/对方”表示人工指定阵营下的裁判数据归属，不是视觉识别能力。BBT不新增机器人检测、装甲识别、目标跟踪或敌我分类模块，也不把其结果作为保底任务启动依赖；自瞄系统承担这些职责。

### 2. 启动、坐标与配置

- 决策必须提供配置及只读 `own_team=red|blue`，不支持 auto；桥与决策选择一致，换边需重启。裁判 robot_id 仅诊断，不选边、核实或单凭身份异常否决购买；桥发送方固定为红方7、蓝方107。
- 当own_team为red时，裁判红方前哨字段归为己方、蓝方归为对方；为blue时反向映射。协议已定义为己方/对方视角的字段直接沿用该视角，不因颜色再交换。此映射不需要场上机器人身份、颜色或位置识别。
- 当前正式配置为39个点、5个区域和6条洞；数量不限制自由坐标指点。原有zone用途标签保持不变，包括home、patrol、outpost、retake；显式巡逻名单只限制巡逻候选，不删除其他点或修改其用途。
- 正式几何以红方为基准，蓝方绕场心 `(14,7.5)` 旋转180度，保持战术ID与敌我含义；随后统一使用场地到地图的旋转、平移。真实点击只做场地到地图变换，不随己方再旋转。
- 当前显式使用恒等场地到地图变换，不代表实车地图已测量标定。输入位置必须和导航目标处于一致的地图坐标系；当前实现直接取里程计位置，不查询TF，不能仅改frame名称冒充变换。
- 位置用于最近巡逻点、近首洞入口、区域几何归属核对、洞口保护、中心通过进度，以及现有自主任务的到达距离兜底。人工指点不得采用该距离兜底判完成。
- 默认20 Hz，可配置1–200 Hz；real仅使用2027协议，legacy用于兼容仿真。real听到sim来源声明后锁存来源保护，进入待机，后续real声明不自动解除。要求地图标定但变换未显式启用时不执行决策。
- 关闭过洞后区域和洞表可省略；在无region/几何的合法模式下，人工有限数值原始XY直接交由导航判断可达性，不因缺少region而拒绝。有几何时仍严格要求唯一归属。关闭前哨功能后不参与前哨争夺。配置校验有限数值、唯一ID、区域引用、阈值与几何一致性。

### 3. 区域几何与过洞判定

- 当前region几何图已由用户确认。各region配置命名多边形，同region可以由多个多边形单元组成，支持由任意有效坐标确认区域。不吸附到最近战术点，也不借最近点的region猜测。
- 区域几何是坐标归属依据。预设点与洞口的region可由几何计算，或保留原字段并加载校验一致；不允许几何与手填字段各自生效、互相矛盾。
- 区域与洞几何同样按阵营和地图变换部署。不同region内部重叠为配置错误；相邻region的共享边界不产生唯一归属，同region单元之间共享边界仍归该region。配置了几何时，有效普通终点应有明确且唯一的区域归属；洞体严格内部、场外、非法数值或不能确定有效归属的坐标不作为新的人工任务，保留上一有效任务。无过洞且合法省略region/几何时，只要求原始XY有限，由导航判断可达性。洞口对正点处于洞体边界时仍可作为入口停车点。不新增面向操作手的提示流程。
- 既有区域记账继续服务过洞执行：开赛初始化、出口导航成功更新出口区；几何可核对当前位置与入口服务侧，洞内不通过最近点随意改区。
- 不同region之间必须通过洞连接图穿越，可以经mid连续过多个洞，不走普通坡道或绕行跨region。保留BFS，最少过洞次数优先，并列按有效位置到首洞入口择近。一条洞完成后重新评估剩余路线，最终仍去原始坐标。
- 普通导航不得跨出本次目标region，或自行穿过未经BBT批准的洞；每次规划结果从当前位置起逐段检查完整线段位于目标region的多边形并集内、且不与洞体相交，再执行审核通过的固定路径，失败重试重新规划和审核。路径穿入别区后再回到目标区同样拒绝。只有折叠确认后才执行当前指定洞穿越。仅对终点判区或只检查离散路径点不构成完整通行保证。
- `gate_clear_m`为配置战术点到洞两端align连线段的最小筛选距离，正式值0.5米，当前39点全部保留。own road最近配置点47距离1.502431米，enemy road最近配置点153距离0.914822米。该筛选只用于配置点，不用于任意原坐标人工目标；人工坐标继续按洞体内部、区域归属及数值等有效性规则处理。

### 4. 自主选点与既有约定

- 没有占优的人工任务时：血量/弹量锁存回家 → 己方前哨夺回 → 对方前哨争夺 → 巡逻。自主购买独立于这条移动优先级。
- HP比例低于30%或已知弹量少于50触发回家；HP至少60%且参与监控的弹量至少150才解除。弹量未知或关闭监控不阻止解除。人工赶路和保护期间照常更新锁存，只压制回家输出；购买已恢复资源时也照常解除锁存。
- 普通自主换点保留连续3帧一致、当前目标生效至少2秒的防抖；巡逻到达锁存可提前满足驻留条件，首次目标立即生效。低血低弹回家仍采用该既有防抖；人工目标更新不套用普通换点延迟。
- 回家锁存成立但家点不可用时，最终停车，不退到前哨或巡逻。
- 前哨的一侧HP与控制码均已知才判断，控制码0完全控制、1临时控制、2未控制。己方HP为0或非完全控制，选第一个可用retake点；否则对方非完全控制时选第一个可用outpost点。缺少可用点则进入后续候选。
- outpost是前往对方前哨阵地的攻击/占领任务；retake是夺回己方前哨阵地任务。outpost前往途中即发布优先攻击对方前哨的意图，不要求到位才提示开火。
- 正式巡逻名单 `patrol_point_ids`为 `[28,40,70,101]`，109、114仅用于outpost任务，其他配置点及原zone标签保留。巡逻继续按显式名单顺序轮换，首次选最近可用点，无定位取第一个；到达或目标生效满15秒后允许轮换，保留未到达也轮换的既有规则。操作者自行配置点表与巡逻名单，不增加高地限制或巡逻禁止过洞的代码条件。名单允许跨region时仍遵守统一过洞契约。无可用巡逻点退家，无家则停车。
- 自主普通点可用匹配目标的导航成功或新鲜位置进入0.5米半径判到达；这不适用于人工目标。洞口成功不能冒充普通任务点到达。
- 不新增HP为0时的导航、停火或自旋停止分支，保留由下位机锁车的约定。HP为0仍参与既有血量锁存和自主复活判断。
- 不新增裁判断流停车或慢更新等同结束的规则，保留最后收到的比赛阶段。已有购买、定位和机构各自的有效性要求仍保留。

### 5. 操作手指点与到点作战

- 操作手导航输入是任意坐标，不要求存在于预设点表。坐标通道为 `/referee/operator_cmd` Float64 `[type,param,seq,x,y]`，消费type=4；测试兼容的ID通道可保留，但不是人工点击的前提。
- 保留原始场地坐标，经坐标变换后作为最终目标，不吸附、不替换。目标跨region则先过洞，之后继续前往原目标。
- 取消从收到指点开始计算的固定120秒过期。单段导航超时与重试继续存在，不是整个人工任务过期。
- 人工赶路时原目标优先于回家和前哨/巡逻，但比赛结束及过洞安全执行条件仍优先。自主购买及血弹锁存照常运行。
- 只有本次人工目标对应的最终导航成功才确认到达；目标是原坐标，容差由导航配置。导航接收、重发、进入0.5米半径、中途入口/出口成功或旧任务回执均不算。本轮删除人工目标距离提前完成与到达即消费的旧行为。
- 最终成功到达时记录一次到达时刻，开始20秒最短保持；保护期内不因回家、前哨或巡逻离点。到点保持是不主动选择其他移动目标，允许普通自旋和攻击，不等同故障停车。
- 脱战采用裁判SentryInfo的out_of_combat字段：true为裁判判定脱战，false为未脱战，不根据有无射击、可见敌人或HP变化自行推断。
- 连续脱战10秒与20秒保护并行计算，均只计到达后的时间。到达时已知脱战则从到达计时；之后首次确认脱战时起计，重复脱战更新不重置，收到未脱战即清零。移动决策持久保存最后已知裁判out_of_combat，不因正常慢更新或超过购买数据的2秒时效而丢失该值、重置计时；尚未收到任何有效脱战值时不能开始累计。按真实时间计算，不按20 Hz决策帧计数，也不把正常裁判更新间隔当作断流停车。该持久语义仅用于移动决策，购买与复活仍要求各自新鲜裁判数据。
- 到达后的判断严格按下表优先级执行；没有人工任务才进入普通自主选点。20秒和10秒为默认可配置值。

| 判断条件，按顺序命中 | 行为 |
| --- | --- |
| 尚未收到本次最终目标成功 | 继续原坐标任务，不启动保持计时 |
| 已到达，但不足20秒 | 保持点位作战，不由普通自主目标抢占 |
| 已到达至少20秒，回家锁存仍成立 | 消费人工任务，进入自主回家选择 |
| 已到达至少20秒，连续脱战至少10秒 | 消费人工任务，恢复普通自主决策 |
| 其他 | 保持点位作战，自主购买继续 |

- 两个退出条件同时满足时回家优先。释放人工任务后，自主目标仍遵守既有换点防抖，不再等待额外人工停留条件。因回家消费任务后，补给完不自动返回旧坐标。
- 示例：到达后一直脱战且不需回家，最早20秒后解除；第18秒交战、第25秒确认脱战，最早第35秒解除；20秒时仍需回家则允许回家，不再等脱战。
- 当前有效任务内相同坐标的重复指点，哪怕序号不同，也不取消或重发导航，不重置到达时刻、脱战计时、导航超时或重试冷却。不用“再点同点”承担故障恢复职责。输入通道各自去重后，按本地接收顺序排队消费；两个决策tick之间的多条输入不能退化为只保留最后一条。无效点击、未知类型或人工购买报文不建立导航任务，也不能吞掉排在其前面的有效坐标。
- 不同的有效坐标建立新人工目标，清空旧到达与保持计时，并取消属于旧目标的普通导航；新任务不继承旧任务失败冷却。从提交中心/出口穿越导航起即保留当前洞的安全事务，不必等定位显示已进入洞体；此后先完成本洞安全穿越/展开，再执行最新目标，不因换点掉头。旧回执不得触发新目标到达。
- 已消费指令不会因缓存报文再次出现而自动恢复；只有实际接收的新有效指令才可建立新任务。桥已有连续相同0x0303载荷去重，本规格不承诺用重复相同点击延长停留。
- 洞内等无效终点静默拒绝，不增加提示流程，不替换成别的坐标。有效目标但执行中导航失败由重试处理，不伪报到达。

### 6. 导航、重试与停车

- 普通目标先调用标准Nav2 ComputePathToPose，审核完整map系路径后再调用FollowPath跟踪该固定路径。默认Action名称 `/compute_path_to_pose`、`/follow_path`，分别由节点参数 `nav_compute_path_action`、`nav_follow_path_action`配置。穿洞采用标准Nav2 NavigateThroughPoses，默认 `/navigate_through_poses`，由 `nav_through_poses_action`配置。
- 普通规划路径不得为空，坐标及frame必须有效，末端须对应本次原坐标；从当前定位开始逐段检查全程位于目标region的多边形并集、且不与任何未授权洞体相交。无过洞且合法省略region/几何时不作虚构的region检查。指定洞穿越成功后仅允许下述出口向外前缀清出，不授权新的过洞或跨region。FollowPath不隐式重规划；路径跨区、不合法、被截短或服务不可用时不交给控制器，不回退到旧PoseStamped执行。
- `/goal_pose` PoseStamped保留为目标观测口，`/nav_cancel`保留兼容取消通知，既有 `/nav_status` 的0空闲、1运行、2成功、3失败仅作观测，不驱动完成判定。旧 `/goal_pose`执行器必须停用，不得与BBT的Action并行发速度。
- 导航回执必须属于当前任务，全部规划、跟踪、穿越请求按代际与Goal身份隔离；取消后迟到的接收、规划结果和成功回执均不能恢复旧目标或完成新目标。过洞入口/出口、中间途经点与最终人工目标不能混淆，不能仅靠一个无身份success值确认任意新指点。
- 运行中目标不变就保持同一次请求；每tick重评不得反复取消/重发。不同新目标先取消自己拥有的旧任务，再提交新目标。
- 发送失败、拒绝、规划路径审核失败、报告失败或单次普通导航25秒未成功，才触发失败处理：取消相关导航、明确停车，等待2秒后重新规划、审核并执行仍有效的同一目标。普通导航不设总重试次数上限。取消120秒任务过期不取消25秒单次超时。
- 重试不消费人工目标，不标为到达，也不启动20秒保持计时。已经成功的任务不因旧超时再次重试。
- BBT不发布普通巡航速度；导航负责平移控制。BBT明确要求停车时取消相关导航、停自旋并发零 `/cmd_vel`，包括入口等折叠、出口等展开、空目标、失败等待、过洞拒绝和比赛结束。导航端须停止旧任务速度，防止覆盖停车。
- 所有明确停车路径执行上述完整收尾。树的每tick重评不重复收尾；等待期间保证停车效果，但不反复创建取消与新目标。
- 战术到点保持允许默认1.5 rad/s自旋及自由攻击，不持续发全零命令压掉自旋；明确故障/机构等待停车才停自旋。2027适配层按自旋需求切ROTOR/独立模式。自瞄主权在外部系统，攻击消息是意图。
- 攻击意图不提供已识别的敌方机器人列表，也不表示目标存在或可以命中。现有前哨目标类别及约定ID表达的是固定建筑任务；自由攻击时由自瞄自行识别敌我、选敌、瞄准和执行射击。BBT不通过敌人识别结果判断脱战，仍只读取裁判的out_of_combat。
- 比赛仅game_progress=4执行运动和自主购买；开赛沿切模式并初始化区域。结束沿一次性取消导航、零速度、停自旋、清攻击意图和人工任务，终止穿越，不主动展开；之后不持续发任务控制，诊断统计与轨迹仍输出，购买可撤销复活确认。

### 7. 过洞树与恢复

- 过洞顺序与恢复由条件、动作和树控制节点表达，保持以下外部顺序和恢复契约。导航、机构反馈及进度证据保存在黑板，不能用阶段状态机驱动。
- 新跨区任务须有有效位置与明确入口侧；无定位时停车等待，不提前锁首洞。无路停车；洞定义无效、机构未知或未折叠却已贴近洞轴等拒绝启动会停车并进入5秒冷却。
- 正常顺序：入口单点成功并停车 → 发折叠 → 收到新鲜已折叠反馈 → 一次提交中心与出口 → 出口导航成功并停车 → 发展开 → 新鲜已展开反馈 → 继续原任务或下一洞。
- 洞center取显式配置，不通过两端align中点推导。中心是连续途经点，不独立发单点目标、不停车、不产生独立成功。无中心的简单走廊直接去出口；多点Action缺失或拒绝时停车重试，不退回中心/出口两个单点任务。
- 穿越期间停自旋、禁火，持续要求已折叠。机构新命令清除旧完成值；反馈默认1秒过期，机构等待默认3秒超时，单段穿越默认25秒超时。
- 失败时取消对应导航、停车，保留实际物理进度。从提交中心/出口穿越任务起即保留本洞事务；车辆已在洞中且折叠确认后恢复时同样保留。5秒冷却是两次失败尝试的间隔，不是任务终止期限；恢复条件仍需真实反馈满足。

| 失败发生时的事实 | 冷却后的恢复 |
| --- | --- |
| 尚未提交中心/出口穿越导航，且车不在洞内 | 可重新选择路线、入口并尝试折叠 |
| 已提交穿越任务或车已在洞内，尚未过中心 | 重新请求并确认折叠，经过中心继续去出口 |
| 有效定位已确认到达或越过中心 | 保留通过证据，只继续去出口，不倒回中心 |
| 出口已到但展开未确认 | 保留出口进度，只重试展开，不重新穿洞 |

- 出口导航成功更新出口区，但未收到已展开反馈前不交还普通导航。中止不代表离开洞口，不自动展开。
- 正式洞出口坐标是洞体边界，导航在约2厘米容差内成功时，实际位置仍可能略在洞内。匹配的指定洞穿越成功后保留该成功事实，允许后续路径的开头沿该出口向外清出该洞体；不能反向、不能离开后再入、不能穿其他洞。region整段约束不放宽，未获得对应穿越成功事实不能使用此前缀授权。这里保存成功穿越的物理事实，不增加阶段枚举或状态机。
- 洞内恢复优先于普通目标变更；比赛结束仍可终止整个事务。树子树中止、目标重评或迟到回执不能清掉进度，不能让普通导航绕过未完成的安全穿越。

### 8. 自主购买、人工购买与复活

- 人工买血、买弹、复活等操作直接作用于裁判系统，BBT不处理这些人工购买指令、不转成另一份自动订单。BBT观察裁判结果，并继续按自身规则自主购买；当前指点通道只消费导航type=4，其他人工类型不参与移动决策。
- 默认自主买弹：弹量少于30且金币至少200，尝试100发；自主回血：活着、HP低于40%、金币至少300且满足脱战，尝试一次。各类规则尝试间隔10秒。买弹、回血的配置策略门槛不等于复活门槛。
- 购买执行仍检查比赛、摘要含源年龄和SentryInfo默认2秒时效、来源保护及未完成请求。买弹/回血要求活着、脱战、远程次数少于15；买弹池至少100、实现费用150；回血实现费用为50加已比赛秒数每3秒向上取整。这里记录已有费用实现，不代替官方规则解释。
- HP为0时自主请求复活：can_free_respawn=true优先免费，不检查金币；否则要求can_buy_respawn=true且金币至少respawn_cost_coin。资格和实际复活费用来自裁判回读。
- 取消付费复活额外200金币门槛，保留明确的自动复活启用/停用配置。裁判报价120、余额150且允许时，应能请求付费复活；有免费资格且余额0时，应能请求免费复活。自主购买总开关关闭、或自主复活开关关闭时不自动请求复活；人工裁判操作不受BBT开关影响。
- 唯一实际执行口是 `/referee/sentry_command` SentryCommand；`/sentry/buy_ammo`、`/sentry/buy_hp`、`/sentry/buy_revive`仅是执行层接受后的意图观测，不接第二个执行器。
- 使用裁判回读累计次数，一次只保留一个未完成自主请求，每200毫秒重发相同计数、最多12秒，不因重发增加新订单。买弹/回血计数确认后，再等6秒到账窗口。复活成功或检测到比赛结束时撤销复活确认。
- 保留已知限制：未确认请求12秒后停止重发，但不自动释放占用；可阻塞后续自主购买，直到匹配回读或既有终止条件出现。本规格不额外改变该购买恢复策略。

### 9. 串口桥、消息与观察

- 裁判消息模块定义19种消息；桥解析比赛、血量、场地事件、警告、机器人状态、热量功率、位置、增益、伤害、弹量金币、RFID、地面位置、哨兵信息与点击，默认保留原始帧。消息类型存在不表示对应通用运行接口存在。
- SharedTopic接收ref_frame、chassis_state、姿态四元数、云台电机角；发送chassis_data、chassis_mode、fold_cmd、ref_tx。桥校验帧长度及CRC，断开后尝试重连；不承诺重连重放此前模式和折叠命令。
- 标准摘要默认20 Hz、14元素，比赛、RobotStatus及弹量金币为必需源；必需源默认2秒过期则停发摘要，可选源独立时效，携带最老必需源年龄。决策兼容10–14元素及历史9/19元素布局。摘要停发不自动改成比赛结束。
- 速度为前、左、逆时针正，单位m/s和rad/s，不交换轴。0 RELAX、1 INDEPENDENT、2 ROTOR、3 FOLLOW；自旋在ROTOR替代角速度。速度默认200毫秒断流后全零，电控另有独立掉线看门狗。
- 折叠命令1折叠、2展开；底盘回传实际机构状态。桥本身不发布定位里程计，不实现雷达坐标变换，不提供通用RefereeTx ROS发包入口。
- SentryCommand经桥校验新鲜比赛/计数、范围和累计单调性后，封装0x0301/0x0120内容段，经ref_tx给下位机组完整裁判帧；接收方0x8080。保持姿态时用已知裁判或底盘姿态，未知则拒发。
- 接口统计1 Hz JSON记录计数、频率、年龄和丢弃；决策轨迹逐tick记录实际目标、区域与执行证据。树重构后诊断可反映节点及物理进度，不要求继续用业务阶段枚举驱动执行。

### 10. 辅助与仿真能力

- 地图辅助工具从测量点解算旋转和平移，可显式写入配置并绘制点位；尺度仅诊断，残差超过5厘米不会自动禁止写入。
- 连续过洞采用六洞套件、标准多点Action仿真服务与物理验收，支持红蓝、正反向与独立域并行。车辆从出生点物理移动到测试侧，不传送、不代填导航或机构成功。
- 旧短局工具可用于单点导航、购买与通信smoke，其普通入口未提供当前连续过洞所需Action，旧中心单点分析不能作为当前穿越验收。
- 混合比赛默认420秒，仅指定一方哨兵由生产BBT控制，其余九台从已有匹配机型策略库独立随机分配；自瞄替身服从BBT意图并只用允许的观察与队内通信。
- 功能演示显式注入测试余额、伤害、前哨归属、死亡和指点，生产BBT执行后续动作。注入条件不是BBT自主获得的能力。
- 保存动作、接口、物理轨迹、源与二进制哈希、策略或刺激、回放与验证报告；每物理tick重放输入，比对保存的采样物理帧和终局digest，未逐tick保存完整物理状态。提供本地只读回放。

## Testing Decisions — 验证边界

主功能验收使用生产决策节点的公开ROS输入/输出与标准Nav2 Action：输入裁判、定位、机构、指点与导航回执，观察目标、取消、零速、自旋、攻击、折叠及购买。最高层外部行为优先，不用内部枚举或函数调用次数替代验收。

沿用真实生产行为树配可控反馈的确定性测试覆盖时序；沿用ROS适配测试覆盖回执隔离及购买；PTY验证线格式，Arena六洞验证真实折叠、连续穿越与展开。已有整节点、树、逻辑、配置、适配与物理验证是先例，不新增测试专用生产入口。

| 场景 | 验收结果 |
| --- | --- |
| 阵营缺失/非法、运行中修改、裁判身份错误 | 配置拒绝或参数只读；不随裁判身份换边 |
| 人工选red/blue，输入相同红蓝前哨裁判数据，不提供机器人识别或跟踪输入 | 己方/对方前哨按人工阵营映射，自主规则仍运行；协议己方视角字段不重复换边 |
| 普通任务、前哨任务、过洞与脱战判断 | 只观察既有攻击意图和裁判脱战字段，不要求BBT检测敌人、分类敌我或证明射击命中 |
| 红蓝几何、地图变换、任意点击 | 几何正确部署；实际点击只变换一次 |
| 任意坐标距所有预设点超过1.5米 | 保留原坐标及其几何region，不吸附 |
| 几何与手填region冲突、洞内/无归属点击 | 配置冲突不静默生效；无效点击静默保留旧任务 |
| 关闭过洞并合法省略region/几何 | 有限原始XY交由导航判断可达性；有几何时仍要求唯一归属 |
| 自由坐标跨多洞 | 正确折叠穿越，最终仍为原坐标，普通重规划不偷穿洞 |
| 不同region经坡道直达或其他区域绕行可达 | 仍按洞连接图执行，可经mid过多个洞，不接受普通跨区路径 |
| 普通路径两端在洞外但中间线段穿洞 | 不进入FollowPath，停车重试，不只检查路径离散点 |
| 同region两端之间的路径穿入别区再回来 | 整段region校验拒绝；同region多个单元并集内路径可执行 |
| 正式配置闸线距离0.5米与任意原坐标 | 全部39配置点保留；人工点不套此距离筛选，仍拒绝洞体内部 |
| 普通规划成功、空路径、截短末端或错误frame | 仅完整合法且末端对应原坐标的路径可执行 |
| 已审核路径执行失败后重试 | 重新规划及审核，不由FollowPath隐式重规划绕过限制 |
| 旧规划迟到、取消后旧目标接收、旧执行成功 | 按代际和Goal身份隔离，不恢复旧任务、不完成新任务 |
| 人工赴点中低血低弹、自主购买 | 不改道；锁存与自主购买持续运行 |
| 重发、入口/出口成功、旧回执、距目标0.5米 | 均不提前判人工目标成功或启动保持计时 |
| 到达后一直脱战且不需回家 | 20秒前保持，满20秒后解除；不是20秒再加10秒 |
| 第18秒交战、第25秒确认脱战 | 最早第35秒解除，重复脱战消息不重置起点 |
| 20秒时仍需回家，且脱战条件也满足 | 回家优先，消费人工任务，补给后不返旧点 |
| 同坐标重复、新坐标替换 | 同点不重发、不复位任何计时；不同点重建任务并隔离旧回执 |
| 同tick前先有效坐标，后无效坐标/购买类型 | 按本地接收顺序消费，有效目标不被后者吞掉 |
| 普通导航失败或单次25秒超时 | 明确停车，等2秒重试原目标；无总次数上限，不冒充到达 |
| 到点战术保持与故障等待 | 前者允许自旋攻击，后者零速停自旋，避免混淆 |
| 血弹恢复一项、巡逻15秒、巡逻点范围 | 保留双条件锁存和原轮换规则，正式巡逻只用28/40/70/101，109/114仅outpost，zone不改 |
| 阵亡、正常裁判慢更新 | 不增加独立死亡停止或断流停车分支 |
| 过洞无位置/未知机构、Action缺失 | 等待或冷却；不直接发跨区目标、不退化中心停车 |
| 中心前后失败、出口展开失败 | 5秒冷却后按真实进度恢复，不倒回已过中心、不重新穿已完成洞 |
| 出口成功但定位略在洞体内 | 仅匹配的指定洞允许路径开头向外清出，拒反向/再入/穿他洞，region约束不放宽 |
| 正反向连续穿越、旧状态和Action结果 | 中心不停，无独立成功，旧回执不完成新任务 |
| 比赛结束及重复树tick | 一次性收尾，零速停自旋清目标；诊断仍输出，不重复发新任务 |
| 人工购买与自主购买共存 | 人工不被BBT再执行，自主按自身条件和累计回读工作 |
| 免费资格余额0；付费报价120余额150 | 开启自动复活时分别请求免费与付费，不被额外200门槛拦截 |
| 购买时效、脱战、费用、池和次数不足 | 已有执行门控有效，意图观测不触发第二次执行 |
| 裁判脱战正常慢更新超过2秒 | 保留最后已知值和连续脱战计时；购买/复活仍遵守2秒新鲜度 |
| 同计数重发、确认、无确认 | 幂等；确认后6秒窗口；无确认12秒停发但保留既有限制 |
| PTY速度、模式、折叠及断流 | SI轴向正确，ROTOR自旋正确，速度断流全零 |
| 六洞、混合比赛与显式演示 | 物理事实可核对，输入全量重放、采样帧与终局一致 |
| 树实现审查 | 无独立业务阶段状态机；流程在树中表达，黑板仅保留必要事实与请求 |

当前原生黑板版本三个包构建成功，10项CTest通过；原始实现的干净导出构建与9项测试结果独立保留在验证记录中。红蓝六洞正反向共24场全部通过，中心邻域最低速度0.2272207m/s，原坐标(11.49,0.58)到达后满足20秒保护及解除时序，坏包为0，源码与二进制哈希一致。三个准备场景各用一次显式停车后的新规划重试，未伪造成功。详细结果及早期失败见 `docs/specs/bbt-implementation-validation.md`。未进行实车验收，历史仿真仍不作为本轮通过证据。

## Out of Scope — 范围外

- 实现定位、建图、自瞄、电控固件或Nav2规划控制算法；本规格要求其集成契约正确。
- 在BBT内实现机器人/装甲检测、敌我识别、目标跟踪、视觉选敌或实际瞄准射击；不为这些能力新增决策启动依赖。
- 以其他策略系统的结构或任务约束BBT；全队协同、胜率优化与新增复杂战术评分。
- 新增巡逻高地区域代码限制，改变用户保留的15秒轮换、死亡锁车或裁判慢更新约定。
- 多车骑压脱困、强制展开、绕过真实机构反馈，以及新增驻点漂移纠偏控制器。
- 未另行确认的购买无确认锁存恢复策略变更。
- 把仿真等同实车间隙、导航取消、速度仲裁和固件看门狗验收，或修改物理/规则来制造成功。
