# 导航接口恢复与接口审计

本轮修改基线为 `10e0910`，依据本次用户逐项答复。历史实现规格不作为新增接口的用户授权。

- 普通任务只发布最终目标；洞入口属于过洞流程。恢复 UC 的 `/goal_pose`（`geometry_msgs/msg/PoseStamped`）、`/nav_status`（`std_msgs/msg/Int32`，0空闲/1运行/2成功/3失败）、`/nav_cancel`（`std_msgs/msg/Empty`）。导航执行端负责规划、避障及到达判定。
- 撤掉 BBT 普通导航的 `ComputePathToPose`、`FollowPath` 依赖及逐段跨区硬拒绝。保留目标区域判定、跨区洞连接图及折叠流程；BBT 不声称可审核外部导航未提供的内部路径。
- 洞任务保留标准 `NavigateThroughPoses([显式中心,出口])`，中心不停留。该 Action 的实机接通尚未确认，仿真服务器不能作为接通证据。普通状态不能确认洞任务；旧洞 Action 结果不能完成后来的普通目标。
- 删除 Arena 强插的出口外扩 0.55 米点及旧洞口残留锁存。模拟导航内部绕障顶点不成为 BBT 目标或停靠任务。
- 保留既有前哨优先于巡逻及更高优先级任务，巡逻名单为28、40、70、101，前哨点109、114；不新增战术点或生命状态规则。
- 红蓝战术模板保留整体换边。用户最新提出导航地图随红蓝换边时点击也要转换；已向用户核对同一裁判物理点在蓝方导航 map 的数值。该坐标约定尚待答复，不将当前代码的点击处理写成实机已验合同。
- 整理 ROS 类型/字段、裁判解析、串口字节格式与可见 MCU 注册表，区分历史基线、仿真替身、当前代码和待现场确认项。

回归边界为已确认的普通目标/状态/取消话题、洞多位姿 Action，以及现有生产行为树和仿真适配测试。普通 `Int32` 状态没有目标身份：可以忽略无任务、取消后及洞任务期间的状态，不能保证区分替换普通目标后迟到的旧终态，文档须保留此限制。
