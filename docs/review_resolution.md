## 已修复

- 冷却、普通导航重试、不可达/空目标的停止取消改成一次性收尾；新目标重新解除锁存。
- 穿洞中丢失折叠确认后停止，冷却后重新请求折叠，等待新反馈再继续出口方向；展开失败保持出口记账与机构恢复事务。
- 指点同点且已经进入到达半径时，仍强制下发一次；不可达/贴洞口点不接受；指点超时默认 120 秒。

- BT 和纯逻辑执行器复用同一比赛门控/收尾函数；增加生产树同点重发与停止节流测试。
- YAML 所有字段转换纳入返回 false/error 的异常契约；校验购买单位、超时、恢复阈值、确认帧数及位姿时效。
- 坐标指点非法值/小数序号计入 dropped；两路指令各自去重，再按本地接收顺序合并，避免跨通道序号饥饿。
- 未知机器人身份不默认当另一方，前哨敌我字段保持未知；补桥侧单独 RobotStatus 断流验证。
- publish 移出 RosPorts 状态锁，增加启用 intra-process 的实际 ROS 测试。
- sim 与 real 共用 2027 裁判/购买/底盘接口；保留显式 legacy 仿真兼容选项，data_source 只负责来源保护。
- 默认话题表与 RosPortsConfig 统一使用 `/sentry/operator_point` 的 Int32 ID 指点和 `/referee/operator_cmd` 的 Float64 坐标指点；两份演示配置同步，省略 topics 时也遵守同一契约。
- 配置中所有已解析浮点字段在读取时拒绝 NaN/Inf，错误保留 YAML 行号；补齐洞坐标、地图变换及几何阈值校验，变换后溢出的洞坐标也拒绝加载。距离、驻留与购买冷却不得为负，保留零值及已有关闭功能的负数哨兵语义。
- 按用户确认直接使用裁判坐标，正式配置启用零旋转、零平移的恒等变换；独立导航地图标定流程保留为可选步骤。Arena 内部 y 方向由适配层统一反转为裁判系。
- 清理过期树注释和重复生成代码；生成的 compile_commands.json 停止 Git 跟踪并忽略，保留本机文件。历史 LibXR 目录保留本地但忽略，不参与构建。

## 未按审查建议修改的项目及依据

1. **远程买弹不能给 exchange_allowance_total 再加 100。** 20261029 协议表 1-33：bit2–12 是补血点的普通兑换量；bit13–16 才是远程兑换请求次数，每次 +1。0x020D bit0–10 明确为“除远程兑换外”的兑换量。当前实现保持普通累计量，仅增加远程次数，正确。PTY 检查两个位域，Arena 中验证真实扣币、受理和 6 秒后 100 发到账。
2. **0x0303 正确长度为 12 字节。** 20261029 协议表 1-35：float x、float y、u8 keyboard、u8 robot_id、u16 source。11 字节固件结构是旧契约，不应使上位机降级。测试同时发送 11 和 12 字节，前者拒收、后者解析并去重。
3. **RobotStatus 断流不会让桥无限发布旧 HP。** publish_summary 在发布前检查 game/status/allowance 三类源的最大年龄；任何一类过期就停止摘要。新增测试让 game/allowance 继续、只断 RobotStatus，确认摘要停止。
4. **intra-process 不等于 publish 同步执行用户订阅回调。** 当前 Jazzy 实现入队后唤醒 executor；因此审查中“开启即死锁”的推论不成立。仍缩短状态锁范围，并在实际 intra-process 下跑折叠、购买和回执测试。
5. **裁判断流后保持最后比赛状态**是原有明确约定，本轮继续保持；购买执行仍要求新鲜数据，折叠反馈独立超时。未擅自把断流伪装成比赛结束，因为那会清理过洞现场并在恢复时错误重置区域。
6. 纯逻辑 step 是有测试用途的入口，不删除。find_tunnel 也被测试使用；串口 rx_names/tx_names 用于 CRC 寻址初始化，不是整套死代码。

## 验证结果

- 当前工作区构建成功，7 个 CTest 目标全部通过（bbt_decide 6、ros2_libxr 1）。
- 新增纯逻辑和 ROS 回归在 AddressSanitizer 下通过，无越界报告。
- `git diff --check` 通过；原点表、洞表、区域归属逐项比较一致。
- 新版协议仿真的坐标点击与 ID 指点分开使用 Float64/Int32 话题。

## 仿真证据

- `runs/arena_default`：原配置短局，读取真实 Arena 状态并运动约 9.98 m；没有声称占位前哨点可达。
- `runs/arena_precise`：60 秒验收配置，约 49.02 m；公路洞入口 13.8 s 到位、22.9 s 出口到位、23.8 s 展开，随后继续运动；两次远程买弹、两次实际到账。
- `runs/arena_fault`：50 秒验收配置，16–20 秒屏蔽机构反馈；验证停止、重新折叠、31.8 s 到出口、32.7 s 展开并继续；实际购买 2 次，其中 1 次在结束前到账，另一次仍在 6 秒延迟窗口。

各目录的 validation.json 由 `tools/check_arena_run.py` 根据物理轨迹、导航到位、真实机构状态、串口计数和引擎购买事件联合判断。replay.json 可载入 Arena 观战页。短局不是完整对抗策略评估，也不证明六洞全部可通行。
