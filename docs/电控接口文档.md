# BBT 电控接口与待接通项

本文件描述BBT桥当前期待的接口，**不代表当前烧录电控已实现**。桥代码沿用本机 `27BT-UC` 上位机快照的 `ros2_libxr`约定，由NUC解码20261029裁判协议、电控转发原始帧；线结构定义以 `src/ros2_libxr/include/ros2_libxr/referee_2027.hpp` 为准。对外类型、完整字段及证据见[接口审查](interfaces/README.md)。被查电控缓存快照没有注册 `ref_frame/ref_tx/chassis_state/fold_cmd`，速度单位与ROTOR语义也不相容，必须逐项接线确认；该快照不能代表其他固件版本。

开局与27BT-UC一致人工指定只读参数 `own_team:=red/blue`，桥和决策使用相同值。裁判机器人ID只作诊断，不推断或核实阵营；桥中购买发送者按人工选择固定为7/107。其他组可继续发布UC全量ROS数据，BBT只消费[接口子集](uc_interface_subset.md)。以下桥约定与下位机实际实现间的差异见[电控线协议审查](interfaces/electrical-wire.md)，不能仅因上位机代码相同就认定电控接通。

导航接口恢复：普通导航使用 `/goal_pose`（`geometry_msgs/msg/PoseStamped`）最终目标、`/nav_status`（`std_msgs/msg/Int32`，0空闲/1运行/2成功/3失败）、`/nav_cancel`（`std_msgs/msg/Empty`）取消，不再依赖 `ComputePathToPose/FollowPath`或普通路径门禁。过洞保留标准 `NavigateThroughPoses([center,exit])`，实机接通尚未验证，Arena仅为仿真替身。详见[导航契约](nav2_waypoints.md)。唯一导航执行端须协调当前普通目标、过洞、取消和停车；Int32状态没有目标ID，无法完全隔离迟到旧终态。BBT明确停车会取消其导航、发零 `/cmd_vel`并停自旋，导航侧须停止旧任务速度；战术到点作战仍允许自旋和攻击。

区域几何用于目标判区，跨区按配置洞图选择流程，可经mid多洞转接；BBT不获取外部导航内部路径，不能保证实际路径逐段留在某region。洞center读取显式配置。出口展开后直接导航至原目标，不另加0.55米外扩点。这些NUC决策不新增电控载荷。巡逻名单为28、40、70、101，109和114仅前哨；人工坐标不套配置点的0.5米闸线筛选。

## SharedTopic 线格式

`0x5A + len[3,BE] + topic_crc32[4,LE] + timestamp_us[8,BE] + CRC8 + payload + CRC8`。
Payload 为小端，名称参与 CRC32，不能只改名称保持旧载荷。

| 话题 | 方向 | 载荷 |
|---|---|---|
| ref_frame | 电控→NUC | 136 B：bus:u8, seq:u8, len:u16, tick_ms:u32, raw[128]；raw 含完整裁判帧 |
| chassis_state | 电控→NUC | 22 B：vx/vy/wz 三个 float，fold_state:u8, posture:u8, buffer_energy_j:u16, power_w:u16, tick_ms:u32 |
| ahrs_quaternion | 电控→NUC | 16 B：float x/y/z/w，Eigen 顺序 |
| yawmotor_angle | 电控→NUC | float，rad |
| ref_tx | NUC→电控 | 136 B：cmd_id:u16, len:u16, bus:u8, rsv[3], data[128]；data 仅内容段 |
| chassis_data | NUC→电控 | 12 B：float vx/vy/wz，m/s、rad/s；对应 ROS linear.x/linear.y/angular.z，不交换轴 |
| chassis_mode | NUC→电控 | u8：0 RELAX / 1 INDEPENDENT / 2 ROTOR / 3 FOLLOW |
| fold_cmd | NUC→电控 | u8：1 折叠 / 2 展开 |

裁判帧：`0xA5 + data_length[2,LE] + seq + CRC8 + cmd_id[2,LE] + data + CRC16`。data_length 只计内容数据，不包括 cmd_id 或 CRC16。

## 机构和底盘

`chassis_state.fold_state`：0 未知 / 1 折叠中 / 2 已折叠 / 3 展开中 / 4 已展开。必须来自真实反馈并持续刷新，建议至少 10 Hz；超过 1 秒无更新决策视为未知。每次新指令都要求后续到位反馈，禁止收到指令即假报到位。

ROTOR 的目标角速度通过 `chassis_data.wz` 传递，0 必须停转；不新增 `chassis_spin` 串口话题。BBT 适配层随旋转需求切换 ROTOR/INDEPENDENT。桥在 cmd_vel 或 spin 过期时清除对应旧控制，cmd_vel 断流默认 200 ms 下发全零速度；电控还须有独立的掉线保护。

## 裁判输入和小地图点击

电控转发各裁判命令原始帧，不维护另一份 NUC 摘要结构。桥发布 14 元素 `/referee/summary`：

| 下标 | 含义 |
|---|---|
| 0–4 | 比赛进度、HP、HP 上限、17 mm 允许发弹量、金币 |
| 5–7 | 己方前哨 HP、己方前哨阵地控制状态、控制状态有效标记 |
| 8–11 | 阶段剩余秒、源时间戳 ms、己方基地 HP、己方累计控制度 |
| 12–13 | 必需源数据年龄 ms、对方前哨 HP |

同时发布 `rm2027_interfaces` 的 RobotStatus、RobotHP、FieldEvent、SentryInfo 等消息。控制状态按己方视角：0 完全控制 / 1 临时控制 / 2 未控制；3 保留、不能当有效占领状态。

`0x0303` 由桥解析成 `std_msgs/msg/Float64MultiArray` `[type,param,seq,x,y]`。地图点击 type=4、param=-1，机器人头像 type=5；服务器重复内容不会产生新seq。用户确认裁判点击以红方侧为原点；官方协议段列float XY米制，未单独重述原点。当前BBT点击仅做一次 `field_to_map`；蓝方导航map是否随出生侧翻转、同一物理点击应如何映射，仍需核实，不由战术模板换边直接决定。

BBT只消费导航type=4，并以原坐标判区和导航，不要求它属于预设点表。操作手买血、买弹、复活直接作用于裁判系统，不转为BBT自动订单；BBT仍独立根据裁判回读执行自主购买与复活。

导航指令按本地接收顺序排队处理，购买类型或无效坐标不能覆盖队列中先收到的有效坐标。无过洞且省略region/几何的合法配置可直接接受有限XY交导航判断，有几何则仍要求唯一归属。到点脱战计时保留裁判最后已知 `out_of_combat`，正常慢更新不清零；购买和复活仍要求默认2秒新鲜裁判数据。

洞出口位于几何边界，导航成功时实际位置可能仍有少量洞内余量；须核对到达容差与真实机构间隙，后续路径由外部导航负责，不用仿真替代实测。

## 购买唯一执行通路

决策发布 `rm2027_interfaces/SentryCommand` 到 `/referee/sentry_command`；桥封装 `0x0301` 子内容 `0x0120`，发送者为本机 7/107，接收者为 `0x8080`，经 `ref_tx` 交给电控组帧发送。

累计发弹量、远程买弹次数、远程回血次数由裁判 `0x020D` 回读同步。远程次数一次 +1，重发相同值；未确认不能跳到下个次数。回血请求不指定 HP 数，恢复量按规则执行。确认计数不代表实际到账，还要等待 6 秒效果延迟。复活请求成功后撤销确认位。

自主复活使用裁判免费/付费资格与实际费用：免费不检查金币，付费余额足够裁判报价即可，不叠加200金币策略门槛。自主购买总开关或自主复活开关关闭时，不自动请求复活，不影响人工裁判操作。

电控不再消费 `ref_buy`，也不能另外消费 `/sentry/buy_*` 再执行一次。`/sentry/attack_cmd` 由自瞄侧按 ROS 契约接入，不新增 `sentry_attack` 串口载荷。

## 联调验收

先用本仓库 PTY 测试验证组帧，再在真机核对：SI 速度轴和大小、ROTOR 的正负/零角速度、折叠真实到位及断流、裁判双方映射、购买回执和重复发送、取消导航与速度仲裁。一次物理串口只由一个桥进程打开。
