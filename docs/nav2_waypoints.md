# 普通目标与洞中心连续途经点

## 普通导航沿用目标、状态和取消话题

BBT 只选择本段最终目标：普通任务发原目标，跨区任务先发所选洞入口，完成过洞和展开后再发原目标。普通任务不增加避障途经目标或中途停靠。接口为：

| 名称 | 类型 | 含义 |
|---|---|---|
| `/goal_pose` | `geometry_msgs/msg/PoseStamped` | 导航 map 系最终目标，由外部导航执行 |
| `/nav_status` | `std_msgs/msg/Int32` | 0空闲 / 1运行 / 2成功 / 3失败，确认普通导航状态 |
| `/nav_cancel` | `std_msgs/msg/Empty` | 取消普通目标，执行端应停止旧任务输出 |

普通导航不再依赖 `ComputePathToPose`、`FollowPath`，BBT不获取外部规划路径，也不逐线段硬拒绝路径。外部导航负责规划、避障及自身内部途经点；图上显示的 Arena 避障折线只是仿真执行端的内部路径，不能证明生产接口返回了路径。

区域几何仍用于确认目标归属，洞连接图仍用于选择跨区洞及多洞流程。不同region任务按该流程过洞；现有接口不能让BBT审核或保证外部实际路径全程留在某region。关闭过洞并合法省略region/几何的简单地图配置，有限XY直接交导航判断可达性。

普通任务单次25秒超时，失败后冷却2秒重试同一目标，不设总重试次数上限。`Int32`状态没有目标ID或请求序号；即使节点清理本地状态，迟到旧成功仍无法与新目标成功完全区分。现场应只有一个导航执行端，按当前目标、取消和停车维护状态；不得宣称本接口能完全隔离旧回执。尤其最终人工目标的成功回执决定20秒保持计时，须核对实际执行端的状态行为。

## 过洞保留标准多位姿 Action，实机待确认

入口是普通单点目标，到位停车后等待真实折叠完成。随后使用 `nav2_msgs/action/NavigateThroughPoses` 一次提交 `[center, exit]`：center取洞表显式坐标，不取两端align中点；它是连续通过的中间位姿，不单独发布 `/goal_pose`，不产生中心成功回执。整个Action只在出口完成，停车后等待展开，再普通导航至原目标。不添加出口外扩0.55米连接点。

无center配置的简单走廊只提交 `[exit]`；恢复时若新鲜定位证明已过中心，同样只提交 `[exit]`，不倒车补中心。过洞失败后冷却5秒，并保留实际进度；出口已到但展开失败时只重试展开。新任务不能中断已启动的安全穿越，比赛结束可终止。

默认Action名称 `/navigate_through_poses`，可按外部实例的namespace设置：

```bash
ros2 run bbt_decide bbt_decide_node --ros-args \
  -p own_team:=red \
  -p nav_through_poses_action:=/sentry/navigate_through_poses
```

**本仓库没有生产 `NavigateThroughPoses` server，实机接通与连续通过效果尚未验证。** 导航组需提供实际server和连续跟踪多位姿的行为树。`FollowWaypoints`逐个单点任务或中心Wait不符合本契约；服务缺失、拒绝或失败时停车重试，不退回中心逐点停车。

过洞Action按Goal身份及请求代际管理接收、结果和取消，普通 `/nav_status`不决定其完成。唯一执行端须协调话题普通目标与过洞Action，避免并行发速度；取消后停止对应旧任务输出。BBT明确停车会取消其导航、停自旋并发零 `/cmd_vel`；入口折叠、出口展开、失败冷却、空目标和比赛结束均属于停车，到点战术保持仍允许自旋和攻击。

Arena只提供仿真替身来验证相同消息和任务语义，不是实机Nav2接线证据。出口到达容差与真实机构空间也须实测，不能用仿真几何代替。

## 当前验收与历史基线

本次普通话题接口恢复、删除普通规划门禁和出口外扩点，必须以当前源码/二进制及测试报告验收；结果见[验证记录](specs/bbt-implementation-validation.md)。对外交接类型、字段和未接通项见[接口审查](interfaces/README.md)，现场逐项检查见[联调手册](field_bringup.md)。

接口恢复前的原生黑板基线曾通过三包构建、10项CTest及红蓝六洞正反向24/24物理仿真，中心邻域最低速度0.2272207m/s、出口最大误差0.0276601m、0坏包；另有原坐标准确到达后的20秒保护记录。三项准备导航各用一次显式停稳后重新规划。这些结果保留为历史证据，不能直接作为本次修改的通过依据。

2026-11-01连续途经点修正的红蓝验收为 `runs/bbt_nav2_six_red_20261101` 和 `runs/bbt_nav2_six_blue_20261101`，当时12/12通过、7项CTest通过，源和二进制哈希一致。中心10厘米邻域最低速度约0.233m/s，同一公路洞旧单点实现约0.0023m/s；比较图在 `runs/nav2_waypoint_validation_20261101`。旧实现先要求中心停车后再发出口，目标切换只花0至0.1秒也不能证明连续途经语义。
