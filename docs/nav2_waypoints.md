# 导航路径审核与洞中心连续途经点

## 普通导航：先审核，再固定路径执行

用户已确认区域几何。不同region之间必须按洞连接图过洞，允许经mid穿越多个洞，不使用普通坡道或绕行跨区。区域多边形使BBT能确认任意坐标属于哪个region，但仅给终点判区不能约束实际路径。普通导航，包括去入口和去人工原坐标，使用下列标准Nav2链路：

```text
ComputePathToPose(target) → 逐段检查目标region并集与全部洞体几何 → FollowPath(已审核固定路径)
```

普通任务没有新的洞穿越授权，从当前位置起，路径每一段必须完整位于本次目标region的多边形并集内；穿入别的region再回来也拒绝。除下述指定洞成功后的出口向外清出前缀外，路径的任意线段进入洞体同样拒绝，不能只检离散采样点。需要过洞时先由决策树选择洞、导航到入口、确认折叠，再进入后述授权穿越链路。普通路径审核失败或Action不可用时停车并按既有2秒冷却重试，重新规划后仍须重新检查；不回退到旧单点执行器。每次普通任务仍有25秒单次超时，不设总重试上限。

关闭过洞并省略region及几何是合法的简单地图模式，有限数值原始XY由导航判断可达性，不虚构region归属。有区域几何时仍严格检查终点唯一归属与路径整段region约束。

`FollowPath`执行审核过的固定路径，不包含隐式全局重规划；不能改用带重规划的普通 `NavigateToPose`行为树而绕过几何检查。实际Nav2控制器和取消输出仍由导航组负责集成。默认Action名称和可配置节点参数如下：

| Action | 节点参数 |
|---|---|
| `/compute_path_to_pose` | `nav_compute_path_action` |
| `/follow_path` | `nav_follow_path_action` |
| `/navigate_through_poses` | `nav_through_poses_action` |

`/goal_pose`仅保留为目标观测口，`/nav_status`仅保留兼容观测，不决定任务完成。必须停用消费旧 `/goal_pose`并自行导航的执行器；否则它会与BBT的Action任务并行，绕过审核且可能覆盖停车。所有规划、跟踪和穿越Action按请求代际及Goal身份隔离，取消后迟到的接收、反馈和结果不能激活旧目标或完成新目标。

## 授权过洞：中心不停留

旧实现把中心发到单点 `/goal_pose`，等导航成功后再发出口。仿真导航按单点契约先减速停车，所以问题同时涉及决策输出的点性质和仿真执行；不能归因成仅仿真减速。2026-11-01按用户明确的实车要求修正。

入口仍是单点导航目标，经上述规划审核链到点后停车并等待真实折叠完成。之后调用Navigation2标准 `nav2_msgs/action/NavigateThroughPoses`，一次发送 `[center, exit]`。center来自洞表显式配置，不由两端align取中点；它是限定路径的中间位姿，整个任务只在出口返回成功，出口停车后等待展开。没有中心配置时只提交 `[exit]`。恢复时若新鲜定位表明已过中心，同样只提交 `[exit]`，不倒车补中心。

默认Action名称为 `/navigate_through_poses`。带命名空间的Nav2实例可以通过节点参数指定：

```bash
ros2 run bbt_decide bbt_decide_node --ros-args \
  -p own_team:=red \
  -p nav_compute_path_action:=/sentry/compute_path_to_pose \
  -p nav_follow_path_action:=/sentry/follow_path \
  -p nav_through_poses_action:=/sentry/navigate_through_poses
```

需要导航侧实际运行Nav2的NavigateThroughPoses服务，并使用连续规划/跟踪多位姿的行为树，仅在当前已批准洞的中心/出口通道执行。`FollowWaypoints`逐个单点任务或在中心插入Wait行为不符合本契约。Action缺失或拒绝时停车重试，不退回逐点停车。旧 `/nav_status` 消息不会覆盖这个Action的状态；结果和取消由各自Goal UUID与请求代际管理。

过洞失败后等5秒再重试；从穿越任务提交起保留本洞事务、中心通过和出口到达的真实证据。尚未过中心则重新确认折叠后经中心去出口，已过中心则仅去出口，出口已到但展开失败则只重试展开。新目标不能中断已开始的安全穿越，比赛结束可终止事务。流程由树条件、动作与控制节点表达，不用独立阶段状态机。

六洞出口坐标在洞体边界，导航按约2厘米到达容差返回成功时，实际里程计位置仍可能稍在洞体内部。后续路径可使用“本次指定洞已成功穿越”的事实，仅允许开头沿该出口向外清出该洞；授权不允许反向运动、离开后再进入或穿过其他洞。整段目标region检查仍然执行，不用放宽region边界来处理这段出口余量。没有匹配的穿越成功事实时，不授予这项例外；它是物理执行证据，不是业务阶段状态机。

当前检出的27BT-UC只有单点PoseStamped导航接口，不能单凭它表达以上路径审核和连续过洞语义。其他UC消息和共享话题保持兼容，导航使用标准Nav2接口补接，不增加BBT私有路径消息。BBT明确停车时取消自己的Action、停自旋并发零 `/cmd_vel`；执行端须停止被取消任务的速度，不能再覆盖停车。

仿真提供同名标准Action服务器，接受配置中既有的中心/出口组合。它在洞轴上连续跟踪出口，中心只约束途经位置，不生成单独的成功回执。该服务器用于仿真验证，实际Nav2的局部控制器和行为树仍需导航组接线验证。

验证要求：规划路径逐段检查；穿出目标region再返回、经其他区坡道绕行和未授权洞路径均不进入FollowPath；同region多个单元并集内的合法路径可通过；无过洞无几何模式接受有限XY；通过审核的固定路径无隐式重规划；一次过洞请求包含显式中心和终点；中心处无停车/取消/成功；反向过洞顺序；折叠丢失取消Action；中心前后恢复；出口成功后仅向外清出、不能反向/再入/穿另一洞；超时；Action服务缺失；旧单点状态、迟到规划和旧Action结果不能完成或重新激活新任务。六洞物理验收额外要求中心10厘米邻域有连续运动、导航始终Running（Idle/Success/Failure均不能代替）、真实折叠穿越和出口展开。
